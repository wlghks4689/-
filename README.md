# 잘되면 밥한끼 — 무료대화 소개팅 앱 프로토타입

기획서 v0.1의 Phase 0~1을 구현한 웹 프로토타입입니다.

## 현재 구현

- Kakao / Google 간편가입 화면
- 프로필 활성화 전 휴대전화 인증 게이트
- 프로필 생성·조회·수정
- 정면 얼굴 사진 1장 필수 업로드 및 심사 흐름(3MB 제한)
- 생년월일 기준 만 나이 계산 및 프로필 카드 표시
- 로그아웃
- 모바일 반응형 화면

현재 SNS 로그인, 휴대전화 인증, 프로필은 브라우저에서 상태만 재현하는 데모입니다. 인증번호는 `123456`이며 실제 개인정보를 입력하지 마세요.
사진 심사 또한 현재는 승인 상태 전이를 재현합니다. 실제 서비스에서는 서버 기반 얼굴 검수, 부적합 판정, 관리자 재심사 및 원본 이미지 접근통제가 필요합니다.

## 실행

```bash
npm install
npm run dev
```

## 임시 결정과 TODO

- 서비스명은 `잘되면 밥한끼`, 대표 슬로건은 `돈 쓰기 전에, 대화부터 해보세요`입니다.
- 웹/PWA 우선으로 제작했습니다.
- 실제 OAuth·SMS 인증·DB·이미지 저장소는 미연결입니다. Kakao/Google OAuth 키, SMS 본인확인 공급자, Supabase 프로젝트 정보가 필요합니다.
- 광고는 제외 기능이 아닙니다. 다만 Phase 0~1의 가입/프로필 흐름에는 배치하지 않고, 이후 탐색 또는 채팅 목록 화면에서 사용자 경험을 해치지 않는 네이티브형 광고 위치를 검토합니다.
- 타깃 지역/연령, 성별·성적 지향 및 추천 구조, 프로필 필수 항목은 확정 전 임시 UI입니다.
- 결제, 채팅 슬롯, 후원, 신고/차단은 현재 Phase 범위 밖입니다.

## 확정 인증 정책

- MVP 간편가입: Kakao / Google
- iOS 배포 시 Apple 로그인 추가
- SNS 로그인은 편의용 계정 인증이며 실제 유일성 검증 수단이 아님
- 최초 프로필 활성화 전 휴대전화 인증 필수
- 미인증 사용자는 프로필 탐색 및 대화 사용 불가
- 동일 휴대전화 인증정보를 이용한 복수 계정 생성 제한
- 하나의 서비스 계정에 여러 SNS 로그인을 연결할 수 있도록 Account Linking 고려

실서비스에서는 원문 전화번호 대신 인증 공급자의 고유 식별자 또는 서버 측 HMAC 값을 저장하고 `unique` 제약을 둡니다. `users`와 SNS 로그인 정보를 분리한 `auth_identities(user_id, provider, provider_subject)` 구조를 사용해야 계정 연결이 가능합니다. 계정 연결·해제 및 탐색/대화 권한 판정은 반드시 서버에서 처리합니다.
